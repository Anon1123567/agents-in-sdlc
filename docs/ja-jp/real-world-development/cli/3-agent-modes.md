まず、プロジェクトに小さな機能を追加しました。しかし、より大きな変更には、さらにしっかりとしたプロセスが必要です。GitHub Copilot CLI は組織の既存のワークフローに沿って動作するため、正しい方法で必要な機能を構築できます。ここからは、イシューを使って機能を実装し、コードが有効であることと、機能が期待どおりに動作することを確認して、最終的にプロジェクトにマージする、一般的なエージェント駆動型開発の流れを学びます。

> [!NOTE]
> この機能のワークフローを進める間は、同じ会話とブランチを使います。通常、異なる種類のファイルには別々のブランチや PR を使いますが、ここでは主要な概念に集中するため、手順を簡略化します。

このレッスンでは、次のことを行います。

- GitHub イシューから新しい Copilot の会話を始めます。
- Plan モードで要件を定義します。
- Autopilot モードで新しい機能を実装します。
- コードをレビューします。
- 転送されたブラウザーで機能を手動で検証します。

この機能の作業を続けながら、リポジトリの手順を更新し、既存の `quality-checks` スキルをカスタマイズし、MCP による検証を追加して QA エージェントを作成し、機能の PR を開きます。

## シナリオ

Tailspin Toys のカタログが増え、利用者はカテゴリや発行者でゲームを絞り込む必要があります。バックログのイシューには機能が記載されていますが、カテゴリを組み合わせる方法など、コーディング前に合意しておく内容もあります。Plan モードで詳細を決めてから、範囲を定めた実装を Autopilot に許可します。

## 背景

AI コーディングエージェントを開発ワークフローに導入しても、基本は変わりません。むしろ、基本がさらに重要になります。多くの開発者は、次のような流れで作業しています。

1. 実装する内容を説明したイシューから始めます。
2. 構築するものの計画を立てます。
3. コードを作成してレビューします。
4. テストを実行して検証します。
5. 新しい機能を手動で確認します。
6. プルリクエスト (PR) を作成します。
7. コードレビューが完了し、継続的インテグレーションが成功したら、コードをマージします。

> [!NOTE]
> チームや組織によって細かな手順は異なりますが、ほとんどの場合はここに示した流れを応用できます。

この標準的な手順に従うことで、AI が生成したコードが要件を満たし、手作業で書いたコードと同じレビューを受けるようにできます。

## 会話モード

**会話モード**によって、エージェントの自律性が変わります。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押すと、モードを切り替えられます。

- **Interactive**: エージェントと一緒に作業します。エージェントは変更を提案し、次の作業に進む前に入力を待ちます。
- **Plan**: エージェントは最初に計画を作成します。このモードではプロジェクトのファイルを編集できません。
- **Autopilot**: エージェントが自律的に作業し、コードの記述、テストの実行、タスクが完了するまでの反復を行います。

最初に Plan モードで計画を確認し、次に Autopilot モードで実装します。

## イシューから始める

フィルター機能に着手する前に、Codespace に戻ってリポジトリとターミナルを準備します。

1. Codespace に戻ります。停止している場合は再起動します。
2. 星評価の PR がマージされていることを確認します。
3. ターミナルが開いていない場合は、<kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押します。
4. `main` を更新し、フィルター機能用のブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLI を起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を 2 回押して **Issues** タブを開きます。
7. <kbd>A</kbd> を押して、すべてのイシューを表示します。
8. 矢印キーを使い、**Allow users to filter games by category and publisher** というタイトルのイシューを選択します。
9. <kbd>C</kbd> を押してイシューをプロンプトに追加し、**Session** タブに戻ります。

プロンプトが `#7`（または同様の番号）で始まることに注目してください。`#` を使うと、GitHub 上のイシューやプルリクエスト (PR) をコンテキストに追加できます。

## フィルター機能を計画する

計画を立てると、機能を実装したりタスクを Copilot に任せたりする前に、実装方法について決めることができます。複雑な作業では、時間をかけて計画を立てることをお勧めします。Plan モードに切り替え、Copilot に計画を作成してもらいましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Plan モードに切り替えます。プロンプトの下にあるモード表示が **Plan** になっていることを確認します。
2. 前の手順で追加したイシューへの参照に続けて、次のプロンプトを入力します。

   ```plaintext
   Create a plan for implementing this feature.
   ```

Copilot が計画を作成します。プロジェクトを調べ、最適な方法を検討します。

3. フィルター機能の動作について質問された場合は、希望に応じて回答します。正解は 1 つではありません。
4. 計画が完成したら、<kbd>Control</kbd>+<kbd>E</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>E</kbd> (Windows/Linux) を押して計画を展開します。
5. 上下にスクロールして計画を確認します。
6. 決めた内容と異なる部分があれば、Copilot に修正を依頼します。

## Autopilot を承認する

計画を作成してレビューしたら、実装に進みます。Autopilot を使って Copilot に作業を任せます。

Autopilot を使うと、Copilot はタスクが完了したと判断するまで問題に取り組みます。

1. **Accept plan and build on autopilot (recommended)** またはインストール済みのバージョンに表示される同様の選択肢を選びます。
2. プロンプトの下にあるモード表示が **Autopilot** になっていることを確認します。
3. Copilot が計画に沿って作業し、コードを生成してテストを実行する様子を確認します。

> [!NOTE]
> 承認すると、すぐに実装が始まる場合があります。計画を先に確認してください。Copilot が依存関係の不足やポートの競合を報告した場合は、チェック完了と見なす前にセットアップの問題を解決します。

## 実装をレビューして検証する

生成されたコードは、ほかのコードと同様に、マージ前にレビューする必要があります。コードをレビューし、サイトを実行して、すべて問題ないことを確認します。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Interactive モードに切り替えます。モード表示が **Plan** または **Autopilot** ではないことを確認します。
2. `/diff` を入力し、フィルター機能の実装とテストを確認します。
3. 結果をイシューと計画中に決めた内容と比較します。
4. コードをレビューしたら <kbd>Esc</kbd> を押して差分ビューを閉じます。
5. プロジェクトのチェック結果を確認し、失敗があれば Copilot に解決を依頼します。

## 新しい機能を試す

コードが問題なさそうでも、実行できるでしょうか。前回と同じようにアプリを起動し、Codespaces で転送されたポートからサイトを開きます。

1. Copilot に次のプロンプトを送り、アプリを起動します。

   ```plaintext
   Start the app so I can try the filtering feature in my browser. Tell me the URL and leave the server running.
   ```

2. Codespaces でポート `4321` が利用可能になったら、**Open in Browser** を選択します。
3. 計画で決めたカテゴリ、発行者、それらを組み合わせたフィルターを試します。
4. リセットと結果が空の場合の動作が、イシューと決定内容に合っていることを確認します。
5. Codespace に戻り、Copilot に起動した開発サーバーを停止するよう依頼します。

## まとめと次のステップ

会話モードを使い分けて、機能を構築してレビューしました。このレッスンでは、次のことを行いました。

- GitHub イシューから新しい Copilot の会話を始めました。
- Plan モードで要件を定義しました。
- Autopilot モードで機能を実装しました。
- コードをレビューしました。
- 転送されたブラウザーで機能を手動で検証しました。

次は、[カスタム手順を使って][next-lesson]コードが文書化された慣習に従って生成されることを確認します。

### ボーナスの演習 - ページネーションを実装する

ゲームが増えるとページネーションが必要になります。この演習で学んだことを使い、Copilot にページネーションを実装してもらいます。次の点を検討してください。

- 既存の手順ファイルを使うなど、ベストプラクティスに従います。
- ページサイズを利用者が選択できるようにするか、固定にするかなど、ページネーションの方法を検討します。
- 希望どおりの実装になるよう、Copilot に必要なガイダンスをプロンプトに含めます。
- Copilot に変更を依頼したりコンテキストを追加したりして、何度かやり取りすることがあります。Copilot と作業するときの通常の流れです。
